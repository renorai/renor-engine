# Código de Conduta

O Renor é um mecanismo de memória para as anotações pessoais das pessoas e suas ferramentas de IA. Trate todas as pessoas que trabalham no projeto com o mesmo cuidado que o mecanismo foi desenvolvido para oferecer à memória de cada pessoa: seja direto, seja específico e presuma boas intenções.

## Padrões

- Critique o código e os projetos, não as pessoas. Explique o que está errado e por quê, apresentando evidências.
- Mantenha as discussões focadas no trabalho. Não são permitidos assédio, insultos, ataques pessoais ou exposição pública vexatória.
- Não publique dados privados: anotações de outras pessoas, credenciais, caminhos pessoais ou qualquer conteúdo de uma memória que não pertença a você.
- Discorde abertamente quando as evidências exigirem e aceite uma decisão depois que ela for tomada.

## Escopo

Este código se aplica a issues, pull requests, revisões, discussões e qualquer outro espaço do projeto, bem como a qualquer pessoa que represente o projeto publicamente.

## Como relatar uma violação

Relate preocupações relacionadas à conduta de forma privada pelo formulário de avisos privados do GitHub: <https://github.com/renorai/renor-engine/security/advisories/new>. Não publique o relato como uma issue pública. Inclua o que aconteceu e onde. Os relatos são analisados pelo mantenedor, e os nomes de quem os enviou não serão divulgados em nenhum registro público sem consentimento.

Vulnerabilidades de segurança devem ser relatadas conforme as instruções de [SECURITY.md](SECURITY.pt-BR.md.md), e não por este processo.

## Aplicação

O mantenedor decide a resposta, de forma proporcional ao dano causado: uma advertência privada, a remoção de uma publicação, um bloqueio temporário dos espaços do projeto ou um bloqueio permanente em casos de conduta recorrente ou grave. O mantenedor pode agir em nome do projeto sem o consentimento de quem fez o relato quando houver um risco evidente para outras pessoas.
